WCAG contrast: the formula, the thresholds, and what a ratio cannot tell you

How relative luminance is computed, why 4.5:1 is not the only threshold, and why passing AA is a floor rather than proof that text is readable.

Short answer: contrast is computed from the relative luminance of two colours, and the WCAG thresholds are 4.5:1 for normal text, 3:1 for large text, and 7:1 / 4.5:1 for the AAA equivalents. The ratio is arithmetic; whether text is comfortable to read is a different question.

The formula

Relative luminance linearises each sRGB channel and weights them by human sensitivity:

L = 0.2126 * R + 0.7152 * G + 0.0722 * B

where each channel is first linearised:

c = channel / 255
c_lin = c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ^ 2.4

The contrast ratio between two colours is then:

ratio = (L_light + 0.05) / (L_dark + 0.05)

The range is 1:1 (identical colours) to 21:1 (black on white). Note the + 0.05: it prevents division by zero and slightly compresses the top of the range.

Two consequences people miss:

  • The relationship is not linear in perceived difference. 4.5:1 and 5:1 look similar; 1.5:1 and 2:1 look very different.
  • Hue barely matters, luminance does. A saturated red and a saturated blue can have wildly different ratios against the same background.

The thresholds

LevelNormal textLarge text
AA (1.4.3)4.5:13:1
AAA (1.4.6)7:14.5:1

“Large text” is defined as 18pt (24px) regular, or 14pt (18.66px) bold. That is larger than most interface text — a 16px label is normal text, no matter how bold it looks.

This is why a designer’s “but it’s a heading” argument usually fails: a 20px semibold heading is not large text by the definition, so it needs 4.5:1.

What the ratio cannot see

A passing ratio is a floor. It does not account for:

  • Font weight and size beyond the threshold. Thin type at 4.5:1 is harder to read than regular type at the same ratio.
  • Background images and gradients. The ratio is between two flat colours. Text over a photograph has a ratio that changes pixel by pixel.
  • Antialiasing and subpixel rendering. Thin strokes can visually disappear even at a compliant ratio.
  • Colour vision deficiency. Contrast helps, but colour alone should never carry meaning — a red error state needs an icon or a label too.
  • Reflections and glare. The reason mobile-first design keeps drifting toward higher contrast.

The practical rule: treat 4.5:1 as the minimum, and treat anything below about 7:1 for body text as an invitation to check it on a real screen in daylight.

Where ratios go wrong in practice

Disabled states. A greyed-out button at 2:1 is a common pattern and a common failure. Disabled controls are exempt from 1.4.3 in WCAG, but “exempt” is not “readable” — a user who cannot read the label cannot tell what is disabled.

Placeholder text. Placeholders are text. They need 4.5:1 like anything else, and they are usually the lowest-contrast element on the page.

Focus indicators. A 1px light-grey outline on white can be technically present and practically invisible. 1.4.11 requires 3:1 against adjacent colours.

Text over images. If you cannot compute a ratio because the background varies, add a scrim. A semi-opaque overlay converts an unmeasurable problem into a measurable one.

Using the checker

The contrast checker takes two colours in hex or rgb() form, computes the ratio, and lists AA and AAA outcomes for both text sizes with text labels rather than colour alone — because a green tick that only differs by hue is its own accessibility problem.

FAQ

Does 4.5:1 apply to icons? Non-text contrast (1.4.11) uses 3:1 for UI components and graphical objects.

Is dark mode harder to get right? It is different: pure white on pure black is 21:1, which is technically excellent and visually harsh. Most systems use an off-white on a dark grey for that reason.

Can I just darken until it passes? Usually yes for text on a light background, but check that the result still fits the palette — a “passing” grey can look muddy next to the rest of the UI.
