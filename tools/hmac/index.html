HMAC Generator

Compute an HMAC over a message with a secret key, using SHA-256 or SHA-512.

Runs locally in your browser crypto.subtle.importKey · sign

The key and message stay in this tab. The key is never stored, logged or included in any request.

Loading the local engine…

How it works

  1. Enter the secret key.
  2. Enter the message.
  3. Choose the digest and output encoding.
  4. Copy the signature, or paste an expected value to compare.

crypto.subtle.importKey · sign

Worked example

Reproducing a webhook signature

A provider signs the raw request body with a shared secret. Pasting the exact raw body and the secret reproduces the header value, which proves whether the mismatch came from the body being re-serialised.

Privacy & limitations

What it does

  • HMAC-SHA256 and HMAC-SHA512
  • Text or hex key input
  • Hex or Base64 signature output
  • Constant comparison against an expected value

What it will not do

  • The tool computes a signature; it cannot tell you whether the key is the right one without an expected value.
  • HMAC does not encrypt the message — the payload remains readable.

Want to verify the privacy claim yourself? Open DevTools → Network, clear the log, then run this tool. No request carrying your file appears. See the full explanation.

Questions people actually ask

Should I HMAC the JSON or the raw body?

The raw bytes. Re-serialising JSON can change key order or spacing and invalidate the signature.

Is the key safe here?

It stays in this tab and is never persisted. Still, prefer a throwaway key when testing.

Why does my signature differ from the provider's?

Usually encoding: hex vs base64, or a newline appended to the body.
