Cron Expression Builder & Explainer

Build a cron expression field by field, read it back in English, and see the next run times.

Runs locally in your browser Custom parser · local next-run computation

Expressions are parsed in this tab. No scheduler is contacted.

Loading the local engine…

How it works

  1. Set each field, or type an expression.
  2. Read the generated explanation.
  3. Check the next run times.
  4. Copy the expression.

Custom parser · local next-run computation

Worked example

“Every weekday at 06:30”

30 6 * * 1-5 explains as “At 06:30, Monday through Friday”. The next-run list confirms weekends are skipped and shows the local timezone used.

Privacy & limitations

What it does

  • Five fields: minute, hour, day of month, month, day of week
  • Plain-English explanation of the current expression
  • Next eight run times in your local timezone
  • Validation of ranges, steps and lists

What it will not do

  • Five-field cron only. Six-field (seconds) dialects are detected and rejected rather than misread.
  • Day-of-month and day-of-week are OR-ed when both are restricted, which is standard cron behaviour and surprises people.

Want to verify the privacy claim yourself? Open DevTools → Network, clear the log, then run this tool. No request carrying your file appears. See the full explanation.

Questions people actually ask

Why is my job running on the wrong day?

If both day-of-month and day-of-week are restricted, cron runs when either matches — not both. Use a single field where possible.

Does this support @daily?

Yes, the common macros are expanded before parsing.

Which timezone are the next runs in?

Your browser's local timezone, stated above the list. Servers often run in UTC, so compare carefully.
